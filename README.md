# host_total · 통합 관제 변경사항 (2026-10-22)

기준 브랜치: `origin/host_total` · 기준 커밋: `487ca9c88ff4e1f06be3af4ebdb1421c1d3da201`. 기존 브랜치 이력을 보존하여 변경을 추가합니다.

## 추가·수정 내용

- continuous-v1 공정: A/B 각각 최대 2개를 하나의 주문으로 처리하며 M1/M2가 교대로 운반합니다. 추가 주문은 진행 중 그래프에 연결하고 기존 요청 ID·완료 결과·BUILD_DONE 증거를 보존합니다.
- 공용 통로에는 AMR 한 대만 진입합니다. 다음 자재 운반과 앞 제품 조립을 겹치되, 다음 조립대 진입은 앞 로봇 출차와 팔2·3 최종 작업 결과를 기다립니다.
- 이미 발행된 주차 이동은 취소하거나 재전송하지 않습니다. 복귀가 시작된 뒤 추가하면 그 결과를 기다려 다음 작업을 연결합니다. 일시정지·실패·재시작 시 자동 동작을 방지합니다.
- CLEAR_ERROR/RESTART, 전체 초기화, 주차 위치·Nav2 준비, 수동 점검 및 실패 단계 재시도 기능을 포함합니다.
- 제작공정과 V2 challenge/ACK 통신을 확인한 뒤 명령을 보냅니다. BUILD_LOAD_A/B 연속 작업과 BUILD_DONE 단계 알림을 사용합니다.
- 최상위 실행기·설정·별칭 예시를 deployment/host/에 포함했습니다. hostrun은 관제만 실행하며 초기 위치 준비는 웹 버튼에서 수행합니다.

## 적용 위치와 확인

로컬 변경본: 백엔드 회귀 테스트 146개 통과. 1~4개 구성, 작업 도중 추가, 이미 주차 중인 로봇 재사용, 오류·일시정지·재시작·중복 결과를 모의 검증했습니다.

`host_web`와 `host_backend`의 `host_total`을 함께 사용합니다. 공개용 IP·SSH 계정·홈 경로는 예시이므로 실제 환경으로 설정해야 합니다.

통합 실행기와 현재 별칭 예시는 [deployment/host/README.md](deployment/host/README.md)를 참고하세요. `hostrun`은 자동 초기 이동 없이 관제를 실행합니다.

# host_backend

관제 공정 제어기와 ROS Action 클라이언트입니다. `host_pkg` 빌드는 Action
인터페이스를 생성하며, 실행 진입점은 `src/host_pkg/src/main.py`입니다.

통합 작업 공간의 관제 PC에서는 다음 명령을 사용합니다.

```bash
bash /home/operator/final_project/start_host.sh --mock
```

웹·rosbridge·rosapi·백엔드가 함께 실행됩니다. 설정·빌드·종료 방법과 현재 공정
기능의 범위는 [최상위 안내](../README.md)를 확인하세요. 공통 실행기는 이 폴더의
기존 `build*`·`install*` 대신 `../.runtime/host/`의 새 빌드를 사용합니다.

`control.py`는 최종 성공 Result로 단계·카운트를 진행하는 공정 제어기이고,
`action_transport.py`는 실제 Burger/Arm 클라이언트, `http_adapter.py`는
`control.html` 연결입니다. `mock_devices.py`는 Domain 149 / LOCALHOST에서만
실행됩니다. 실물은 `--mock` 없이 실행하며, 기본 `/web_to_ros` 시뮬레이션
재생 값은 새 주문을 시작하지 않습니다.

### 제작공정 V2 연결 (2026-10-22)

실물 팔2·3 서버의 `/workcell/supervision/status` challenge를 호스트가 heartbeat로 돌려보내고, 같은 nonce의 ack를 확인한 뒤 V2 JSON Action 요청을 전송합니다. 서버 세대(epoch) 변경이나 연결 만료 시 새 작업을 차단하며, 자동으로 재전송하거나 초기 이동을 실행하지 않습니다. 모의 장치는 기존 문자열 명령을 유지합니다. 비상정지는 연결 확인이 만료돼도 서버가 지원하는 `EMER_STOP` 경로를 사용합니다. 최종 결과가 UNKNOWN/PENDING/STORAGE_PENDING이면 작업 완료로 간주하지 않습니다.

### 2026-10-22 주문 대기열·이동 초기화

- A/B 각각 0~2개를 지정하고 `products` 순서에 맞춰 기존 SELECT/BUILD_LOAD/LOAD 명령을 생성합니다. 기존 단일 제품 주문도 유지합니다.
- 최대 2개씩 묶고, 공정 중 추가 주문은 FIFO 대기열에 영속 저장합니다(대기 최대 32개). 현재 작업은 바꾸지 않습니다.
- 다음 묶음은 모든 작업 완료 후 팔레트 비움 확인과 현재 queue_revision을 받아야 시작합니다. 오류·관제 재시작 시 자동 재생하지 않습니다.
- 실패 주문 초기화·전체 초기화는 대기열도 기록 후 비웁니다. 대기 주문 삭제는 현재 묶음을 유지합니다.
- M1/M2 이동 초기화는 실패한 개별 이동의 정지 IDLE 응답 → RESTART IDLE 응답을 확인한 뒤 남은 작업 잠금을 해제합니다. 위치/Nav2 재설정이나 이동 목표를 보내지 않습니다. 시간 초과·연결 끊김은 성공으로 처리하지 않습니다.
